== Summary =================================================================

Confirmed: the WH-CH520 answers the same NCASM_GET_PARAM 0x17 as the
WH-CH720N, with the same 7-byte v2 payload shape, and reports NC on/off,
Ambient on/off, voice and a level byte the same way. Battery is a single
figure over Fast Pair (see the shell's `omaphones status`, not this probe).

Not confirmed, across four separate connections and both an "off" and an
"ambient" attempt with waits of 13-15s after each write and no press of the
headset's own button during any of them: NCASM_SET_PARAM 0x17 changes
anything the headset reports back. Every SET frame this probe sent was
ACK'd at the transport level and left the reported NC/Ambient/level/voice
state exactly as it was before the write. Whether the headset's own button
can still move it through these states (and have that show up over this
same channel) was not tested here — this session has no way to press it.
